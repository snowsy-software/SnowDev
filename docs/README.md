# SnowDev 文档地图

这里是维护者、贡献者和 AI 协作者的文档入口。规范优先于手边代码；若实现与规范冲突，先确认是否为已知迁移状态，再修正实现或规范，不要悄悄引入第二套行为。

## 阅读路径

| 任务                                | 必读文档                                                           |
| ----------------------------------- | ------------------------------------------------------------------ |
| 任何代码改动                        | [工程规范](rules/工程规范.md)、[测试规范](rules/测试规范.md)       |
| CLI、配置字段、hook 或 Compose 行为 | [总体架构](总体架构.md)、[配置与命令规范](rules/配置与命令规范.md) |
| 子进程、环境、日志或危险操作        | [安全规范](rules/安全规范.md)                                      |
| 从旧脚本迁移到 SnowDev              | [迁移指南](迁移指南.md)                                            |
| 本地安装、检查或打包                | [本地开发](ops/本地开发.md)                                        |
| GitHub 私有包发布                   | [发布门禁](release-gate.md)                                        |

## 文档分工

- `总体架构.md`：说明产品边界、core/custom 模型和目录职责。
- `迁移指南.md`：把散落脚本迁移到统一命令契约的步骤与命令映射。
- `rules/`：正式、可执行的开发与审查规则。
- `ops/`：本地开发、验证与发布前操作说明。

若新增一项需要长期遵守的约束，应写入 `rules/`；若只是解释当前设计，写入架构或说明文档；若是可执行的操作流程，写入 `ops/`。
