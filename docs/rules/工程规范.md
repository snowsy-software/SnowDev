# 工程规范

## TypeScript 与模块

1. 源码使用 TypeScript ESM；Node 内建模块必须使用 `node:` 前缀。
2. 相对 import 必须使用编译后的 `.js` 扩展名，以符合 `NodeNext` 解析。
3. `strict` 是默认要求；禁止用 `any`、不安全类型断言或 `@ts-ignore` 逃避问题。
4. 公共类型放在 `src/types/`，运行时输入必须经 `src/schema/` 校验，不能只依赖 TypeScript。
5. 对外导出的类型、函数、类以及影响安全/优先级的行为必须写 JSDoc；注释解释意图和边界，不重复显而易见代码。

## 代码组织

1. CLI 只负责解析、输出和退出码；通用逻辑不得堆入 `cli.ts`。
2. `commands/` 负责编排，`core/` 负责可复用的无业务实现。
3. 新增配置字段时，必须同步更新类型、schema、默认行为、文档和测试。
4. 错误使用稳定的 `SnowDevError` code；用户可见错误经统一格式化，不泄露堆栈、环境变量或敏感路径以外的秘密。

## 变更纪律

保持最小可验证改动。不要新增“兼容层”“mock”“debug”主路径来绕开现有契约。格式化仅覆盖改动文件，避免制造无关 diff。
