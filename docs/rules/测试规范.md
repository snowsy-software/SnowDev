# 测试规范

## 最低要求

1. 每个 bug 修复先添加或更新能复现问题的测试。
2. 配置、参数构造、环境优先级、脱敏、错误码和安全拦截优先使用单元测试。
3. 新工作流类型或命令路径必须有脱敏 fixture；fixture 不得指向真实 Docker daemon、业务仓库或秘密文件。
4. 子进程测试应替换 runner，断言 executable 与参数数组；不得依赖本机 shell 行为。

## 质量门禁

提交前执行：

```bash
npm run typecheck
npm run lint
npx prettier --check .
npm test
npm run pack:check
```

若某项无法运行，完成说明必须写明原因、未覆盖的风险和建议的复验命令。
