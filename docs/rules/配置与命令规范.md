# 配置与命令规范

## 配置

1. 默认且唯一支持的配置文件是项目根目录的 `snowdev.config.mjs`；第二阶段之前不支持 `.ts` 配置。
2. 配置必须默认导出对象，并在执行前通过 schema 校验。
3. `compose.file` 与 `compose.projectName` 必填；每个 profile 必须声明受支持的 `kind` 和至少一个服务。
4. 不接受任意 shell 命令字符串、秘密值或未受控 destructive hook 作为配置能力。
5. `profiles.<name>.health` 可选，声明 HTTP 就绪探针：`url` 必填，`timeoutMs`、`intervalMs` 为可选正整数（默认 60000 / 1000）。
6. `profiles.<name>.host` 描述宿主进程，`kind` 为 `host-app-with-compose-deps` 时必填：`command` 必填，`args` 为字符串数组，`stopGraceSeconds` 为可选正整数（默认 10）。`command` 与 `args` 只作为可执行文件与参数数组使用，永不经 shell 解释。

## Compose 与进程

1. 进程调用只能传递 executable 与参数数组，固定 `shell: false`。
2. Compose 调用始终显式使用 `docker compose --project-name <name> -f <file> --profile <profile>`。
3. 参数不得经字符串拼接后交给 PowerShell、cmd、bash 或其他 shell 解释。
4. 新增 Compose 子命令必须测试含空格的 project name、服务名或路径参数，保证 Windows/Linux 的参数边界一致。

## 环境优先级

环境变量按从低到高的顺序合并：配置默认值、`.env`、`.env.<profile>`、`.env.local`、`.env.<profile>.local`、当前进程环境。环境加载不执行命令替换、插值或 shell 表达式。

## 命令语义

`run stag` 与 `run prod` 永远不得隐式 `docker compose down`。volume 删除只能由明确的 `reset dev --yes` 触发，且不得允许 staging 或 production 重置。尚未实现的命令必须清晰失败，不能伪装成成功。

已实现的生命周期命令：

- `run <profile>`：按 `kind` 启动。`compose-service` 前台 profile（默认 `dev` 或 `foreground: true`）以 `up` 附着运行；后台 profile 以 `up -d --build --wait` 启动。`host-app-with-compose-deps` 先以 `up -d --wait` 启动依赖服务，再启动宿主进程（前台附着，后台写 PID）。`container-cli` 对每个服务执行 `run --rm`。任一路径都不会发出 `down`。
- `down [profile]`（默认 `dev`）：显式停止。对 `host-app-with-compose-deps` 先受控停止宿主进程（SIGTERM，宽限期后 SIGKILL），再 `docker compose down --remove-orphans`。绝不传 `--volumes`。
- `logs [profile]`（默认 `dev`）：默认 `logs -f`；`--no-follow` 只打印一次。
- `ps [profile]`（默认 `dev`）：`docker compose ps`，并附带宿主进程 PID 状态。
- `init [profile]`（默认 `dev`）：首次初始化，创建 `.snowdev/` 并 `up -d --build`。打印影响范围，必须带 `--yes`。
- `reset [profile]`（默认 `dev`）：仅允许 `dev`；打印影响范围，必须带 `--yes`；执行 `docker compose down --volumes --remove-orphans`。
- `task <name>`：读取 `config.tasks.<name>`。`isolated` 任务使用 `"<projectName>-task-<name>"` 作为 Compose project 名（与任何 profile 都不同），并在 `finally` 中执行 `down --volumes --remove-orphans`；非隔离任务清理时不传 `--volumes`。

## 运行时状态

宿主进程 PID 记录写入消费项目的 `.snowdev/<projectName>-<profile>.host.json`。该目录由 SnowDev 维护，消费项目应将其加入 `.gitignore`。
