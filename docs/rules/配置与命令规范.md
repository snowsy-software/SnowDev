# 配置与命令规范

## 配置

1. 默认且唯一支持的配置文件是项目根目录的 `snowdev.config.mjs`；第二阶段之前不支持 `.ts` 配置。
2. 配置必须默认导出对象，并在执行前通过 schema 校验。
3. `compose.file` 与 `compose.projectName` 必填；每个 profile 必须声明受支持的 `kind` 和至少一个服务。
4. 不接受任意 shell 命令字符串、秘密值或未受控 destructive hook 作为配置能力。

## Compose 与进程

1. 进程调用只能传递 executable 与参数数组，固定 `shell: false`。
2. Compose 调用始终显式使用 `docker compose --project-name <name> -f <file> --profile <profile>`。
3. 参数不得经字符串拼接后交给 PowerShell、cmd、bash 或其他 shell 解释。
4. 新增 Compose 子命令必须测试含空格的 project name、服务名或路径参数，保证 Windows/Linux 的参数边界一致。

## 环境优先级

环境变量按从低到高的顺序合并：配置默认值、`.env`、`.env.<profile>`、`.env.local`、`.env.<profile>.local`、当前进程环境。环境加载不执行命令替换、插值或 shell 表达式。

## 命令语义

`run stag` 与 `run prod` 永远不得隐式 `docker compose down`。volume 删除只能由明确的 `reset dev --yes` 触发，且不得允许 staging 或 production 重置。尚未实现的命令必须清晰失败，不能伪装成成功。
