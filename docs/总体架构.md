# SnowDev 总体架构

## 目标与边界

SnowDev 统一项目周边的开发工作流入口：Docker Compose 参数、环境加载、健康检查、日志和受控生命周期。它不替代 Docker、npm 或应用框架，也不生成消费者的 Compose、Dockerfile 和业务代码。

```text
SnowDev core（本仓库 / npm 包）
  ├── CLI 与统一错误格式
  ├── 配置发现与 schema 校验
  ├── 无 shell 子进程执行
  ├── Compose 命令构造
  ├── 环境加载与日志脱敏
  ├── 生命周期：run / down / logs / ps / init / reset / task
  ├── 健康等待：HTTP 探针与 Compose healthcheck，含超时与失败诊断
  ├── 安全机制：禁止隐式 down、reset 仅限 dev、破坏性操作需 --yes
  ├── 宿主进程：host-app-with-compose-deps 的启动、PID 状态与受控停止
  └── doctor

Consumer custom（消费项目）
  ├── snowdev.config.mjs
  ├── Docker Compose 文件
  ├── .env* 本地环境文件
  └── 项目专属、受控的配置
```

## core/custom 规则

`core` 是版本化、不可由消费者复制修改的通用能力；`custom` 是消费项目负责的配置和运行资产。core 不得包含客户、业务、网络、账号或秘密信息。custom 不得通过复制 core 源码来定制行为，应通过稳定配置契约升级。

## 源码职责

| 目录             | 职责                           |
| ---------------- | ------------------------------ |
| `src/cli.ts`     | 顶层参数解析、帮助和进程退出码 |
| `src/commands/`  | 单个命令的编排与用户可见诊断   |
| `src/core/`      | 无业务含义的通用实现           |
| `src/schema/`    | 对外配置的运行时校验           |
| `src/types/`     | 稳定的 TypeScript 契约         |
| `test/fixtures/` | 脱敏、最小化的跨工作流测试输入 |

## 支持的工作流

1. `compose-service`：应用和依赖均作为 Compose 服务运行。
2. `host-app-with-compose-deps`：Compose 只运行依赖，应用运行在宿主机。
3. `container-cli`：容器是一次性 CLI，不是长期服务。

新增工作流类型是公开配置契约变更：必须补 schema、类型、fixture、Windows/Linux 参数测试和迁移说明。
