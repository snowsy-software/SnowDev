# 迁移指南：从散落脚本到 SnowDev

面向已有 `scripts/start.js`、`scripts/runtime.mjs`、`scripts/stop.js` 之类入口的项目，说明如何迁移到统一命令契约。目标是保持 `npm run dev/stag/prod/down/logs/test` 入口不变，把重复实现的 Compose 参数、环境加载、进程处理和 profile 校验交给 core。

## 1. 命令映射

| 旧做法                                       | SnowDev 命令                                  | 说明                                                   |
| -------------------------------------------- | --------------------------------------------- | ------------------------------------------------------ |
| `node scripts/start.js` / `npm run dev`      | `snowdev run dev`                             | 长期服务默认前台；`container-cli` 逐个 `run --rm`      |
| `node scripts/runtime.mjs stag` / `... prod` | `snowdev run stag` / `snowdev run prod`       | `up -d --build --wait`，绝不隐式 `down`                |
| `node scripts/stop.js`                       | `snowdev down [profile]`                      | 显式停止；宿主进程先 SIGTERM 再 SIGKILL；绝不删 volume |
| `docker compose logs -f` 包装                | `snowdev logs [profile]`                      | 默认跟随；`--no-follow` 只打印一次                     |
| `docker compose ps` 包装                     | `snowdev ps [profile]`                        | 附带宿主进程 PID 状态                                  |
| `npm test` 里手搓的隔离 compose              | `snowdev task test`                           | 独立 project 名 + `finally` 清理（含 volume）          |
| 启动脚本里隐式 `down -v` / 重建开发库        | `snowdev reset dev --yes`                     | 破坏性、显式、打印影响范围、仅限 `dev`                 |
| 启动脚本里隐式建库 / 播种                    | `snowdev init dev --yes` 或 `hooks.beforeRun` | 首次初始化显式化；常规准备放 hook                      |
| 脚本里 `execSync("...")` 拼 shell            | `hooks` 里的 `exec(cmd, args[])`              | 只接受参数数组，无 shell，命令进日志                   |

## 2. 配置迁移步骤

1. **盘点**：列出每个环境（`dev` / `stag` / `prod` / `test`）实际起哪些 Compose 服务、用哪个 Compose 文件、宿主机是否也跑进程、端口和依赖健康条件。
2. **生成骨架**：在项目根运行 `npx snowdev init template <kind>`（`compose-service` / `hybrid-host-service` / `container-cli`）。它落地 `snowdev.config.mjs`、`docker/compose.yml`、`.env.example`，已存在的文件一律跳过。
3. **填 `snowdev.config.mjs`**：把盘点结果写成 `profiles`（每个声明 `kind` 和 `services`）、`tasks`（隔离测试）、必要时 `profiles.<name>.health` 和 `profiles.<name>.host`。
4. **迁移环境文件**：把散落的 env 读取改为 SnowDev 固定优先级：配置默认值 < `.env` < `.env.<profile>` < `.env.local` < `.env.<profile>.local` < 进程环境。不再做命令替换或 shell 插值。
5. **把脚本里的临时逻辑改成具名 hook**：启动前准备 → `beforeRun`；依赖起来后跑迁移 / 播种 → `afterDependenciesReady`；停止前导出 / 备份 → `beforeDown`；非容器的 lint / codegen → `hooks.task.<name>`。hook 内需要跑命令时用 `exec(command, args[])`。
6. **改 `package.json` scripts**（SnowDev 不会替你改）：

   ```json
   {
     "devDependencies": { "@snowdev/cli": "1.0.0" },
     "scripts": {
       "dev": "snowdev run dev",
       "stag": "snowdev run stag",
       "prod": "snowdev run prod",
       "down": "snowdev down",
       "logs": "snowdev logs",
       "test": "snowdev task test",
       "doctor": "snowdev doctor"
     }
   }
   ```

7. **校验**：`npx snowdev doctor` 检查 Node、Docker、Compose、配置、Compose 文件是否齐备。

## 3. 兼容层与弃用

- 迁移期可保留旧脚本作为薄包装：内部改成调用 `snowdev ...`，并在开头 `console.warn` 打印弃用提示，指向本指南。
- 旧脚本至少保留一个发布周期再删除。
- 隐式的开发库重置必须显式化：先给出 `snowdev init dev` / `snowdev reset dev --yes` 的迁移提示，不要在 `run` 路径里保留任何隐式 `down -v`。

## 4. 行为差异清单

- `run stag` / `run prod` 不再隐式 `down`；需要停时显式 `snowdev down`。
- volume 删除只有 `snowdev reset dev --yes` 一条路径，且拒绝 `stag` / `prod`。
- 所有子进程用参数数组执行，`shell: true` 被禁止；Windows 与 Linux 的参数边界一致。
- 测试使用独立 Compose project 名，清理不影响 `dev` 数据。
